Forma 是一个用自然语言创建小应用的工作空间。用户描述想法后，可以查看生成进度、运行应用、继续对话修改，也可以直接编辑源码、保存版本和恢复历史。

建议评审先走一遍这个流程：注册登录 → 输入一个小需求 → 生成并操作应用 → 提一条修改要求 → 查看源码和版本。还可以在生成过程中主动中断，再进入项目恢复任务。

没有模型 Key 时，可以选择明确标注的基础示例，体验编辑、预览和版本流程。根据自由需求生成应用，需要配置平台模型，或在界面中连接自己的 API Key。

## 实现思路与取舍

这版先把一条完整的使用路径做稳：用户能创建项目，生成真实文件，看到运行结果，再继续修改。围绕这条路径，我主要做了下面几项取舍。

**先限定生成范围。** 当前支持无需安装依赖的 HTML、CSS 和 JavaScript 小应用。这样每次生成都能交付完整源码，也能在浏览器沙箱中直接预览。代价是暂时不支持 npm 工程、任意后端服务和外部联网能力。

**按当前规模选技术。** 前端使用原生 HTML/CSS/JS，编辑器接入 CodeMirror；后端使用 Python，数据保存在 SQLite。这个组合适合当前的单机 Demo，启动步骤少，问题也容易追踪。前后端已有独立目录、测试和启动命令，可以分开运行和部署。前端目前仍有依赖加载顺序的 classic scripts，模块化还需要继续整理。

**把模型接入和任务流程分开。** 平台模型与用户自己的 Key 共用生成、校验和版本逻辑，协议差异集中在适配层。目前接入了 OpenAI 兼容接口、Responses、Anthropic、Gemini 和 Azure Responses。DeepSeek 做过真实生成与修改验证，其余协议目前主要通过本机模拟服务验证，实际模型权限和额度仍取决于用户账号。

**让保存、检查和预览各有明确含义。** 编辑器保存的是草稿，预览运行的是成功版本的源码快照。检查失败时保留草稿和上一版预览，并显示文件及错误位置。我在验证中遇到过 HTML 缺少引号仍提示通过的问题，原因是解析器会容错；后来补了独立的 HTML 检查，并加入源码修订号校验，避免多页面编辑时误用旧内容。检查覆盖语法和资源等已实现规则，应用运行是否符合需求仍需要实际操作验证。

**让恢复有可复用的进度。** 任务保存原始需求、源码上下文和完整输出检查点。恢复时优先复用已有源码；源码已经被用户改动时，会拒绝直接覆盖。这里实现的是应用层会话恢复：没有完整输出时仍需重新请求模型，尚未实现 Provider 原生的 token 续传。

## 当前完成情况

| 部分 | 已完成 |
| --- | --- |
| 产品流程 | 首页、注册登录、项目空间、方案确认、生成进度和工作台；支持浅深色与响应式布局 |
| 生成与修改 | 平台模型、自带 Key、生成记录、有限自动修复、任务中断与恢复 |
| 源码与数据 | CodeMirror 编辑、草稿保存、文件上传查看、源码版本、历史恢复和源码导出；应用运行数据独立保存 |
| 扩展能力 | 上传 Markdown/ZIP Skill；支持一个主导 Skill，以及风格、架构、交互、质量检查等局部插入点 |
| 资源控制 | 单用户最多 3 个运行中任务，另有全局执行槽位、队列、平台任务额度和存储配额 |
| 工程交付 | 前后端分目录，统一检查、测试和静态发布命令，附架构说明与 Nginx 配置示例 |

Skill 的配置会在任务启动时保存为快照，修复和恢复沿用这份快照，避免运行中修改个人库影响原任务。当前 Skill 提供指令与文本参考资料，包内脚本不会在服务器执行。

交互上，我尽量让用户直接描述目标，细节可以在工作台继续打磨。生成进度读取后台任务状态；等待动画只作视觉展示。现阶段还没有实现主动需求澄清，遇到缺少关键条件的需求，仍需要用户在后续对话中补充。

## 验证与安全边界

最近一次验证通过了 **99 项后端测试和 8 项前端测试**，前端语法检查与静态发布也已通过。测试使用临时数据库和模拟模型服务，覆盖账号隔离、文件冲突、坏源码保留成功预览、任务恢复、并发准入、模型协议、Skill 快照和静态资源访问等路径。浏览器另走过登录、生成预览、编辑保存、版本更新，以及前后端分开运行的流程。

生成代码在无同源权限的 iframe 中运行，服务端不执行生成程序。后端对项目读写检查所属账号，数据库使用参数绑定，上传包有路径和大小限制，用户提供的模型地址也有公网校验。用户 Key 只保留在服务内存中，退出或重启后清除。

目前仍是单机 Demo。应用层做了连接、请求和任务限额；公网部署还需要上游 DDoS 防护、源站防火墙、模型费用硬额度和监控。现有测试不能证明已经覆盖所有攻击，Nginx 模板也尚未在部署环境验证。具体措施和限制见 [安全说明](../SECURITY.md)。

## 如果继续投入时间

**第一优先级：完成公网交付和故障排查能力。** 部署 HTTPS Demo，开放评审访问，接入可用性监控、错误记录、费用告警和数据库备份，并在真实部署环境重跑关键流程。先让别人能稳定访问，也让失败有据可查。

**第二优先级：提高生成成功率和反馈质量。** 补充生成页面的浏览器交互验证，进一步区分语法错误、运行错误和需求偏差；只在缺少关键条件、确实会卡住实现时向用户澄清，并提供容易回答的选项。

**第三优先级：处理扩展后的工程成本。** 逐步整理前端模块依赖，拆分后端较集中的业务编排。需要多实例时，再把进程内限流、任务队列和临时 Key 管理迁到共享基础设施；支持 npm 工程或服务端生成前，先设计独立的构建与运行隔离环境。

当前还未实现邮箱验证、密码找回、团队协作和分布式调度。这些会结合实际部署和使用需求排期。
